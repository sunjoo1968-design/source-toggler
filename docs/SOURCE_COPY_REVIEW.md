# OBS 소스 복제 호환 검토

검토 대상: Camera MIX Controller 1.3.4 / 제작자 SunjooAn

OBS 32.2.2의 스튜디오 모드에서 소스 복제를 사용해 Preview와 PGM을 독립적으로 유지하는 기능을 검토했습니다.

## 확인 결과

- ME1의 Source Switcher는 복제 금지 플래그를 사용합니다. OBS에서 복제를 요청해도 원본 인스턴스를 반환합니다. Preview에서 선택을 바꾸면 PGM도 같은 출력 상태를 공유할 수 있습니다.
- ME2의 native Fade를 포함하는 출력 장면을 소스 복제로 복사하면 자막은 남지만 Fade의 현재 카메라 연결은 복사되지 않습니다. 테스트에서 카메라 영역은 검은 화면이었습니다.
- 따라서 Lua 설정 변경만으로 두 ME 모두의 소스 복제를 완전히 지원할 수는 없습니다.

## 구현 방향

복제 가능한 전용 출력 플러그인을 추가하고, 복제 시점의 선택 카메라와 배치를 보존하는 방법이 적합합니다. Preview의 이후 변경은 TAKE 전까지 PGM에 반영되지 않아야 합니다. 카메라 장치 자체의 복제 여부는 각 OBS 소스의 정책을 따릅니다.

기존 탈리에서 카메라 장면을 배정한 경우에도 복제 출력의 실제 경로를 인식하도록 OBS 탈리 브리지에 원본 대응 정보 해석을 추가하는 호환 작업이 필요할 수 있습니다. 현재 정상 사용 중인 탈리에 대한 수정 범위는 사용자 답변 후 확정합니다.

## 검증 및 현재 상태

`tests/source-copy-probe.py`에서 별도 libobs 엔진을 사용해 위 두 제한을 재현했습니다. 기존 native CUT/MIX 및 배치 검증도 통과했습니다. 현장 OBS를 종료하거나 설정을 변경하지 않았습니다.

현재 단계는 검토 및 재현 완료입니다. 새 출력 플러그인 구현과 현장 설치는 아직 완료하지 않았으며, 기존 1.3.4의 동작을 유지합니다.
